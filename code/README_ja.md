# SIGA再シミュレーション：二値偏差0.12・M3 Ultra単独実行版

## 1. 今回確定した設定

主要評価は32シナリオです。因子数と総標本サイズは (F,n)=(2,200),(5,400)、割付確率は0.8、アウトカムは連続・二値、効果偏差の方向は第1因子と最高次交互作用です。優越性・非劣性について第一種過誤率と検出力を評価します。

| 項目 | 設定 |
|---|---|
| 第一種過誤率 | 各100,000試験 |
| 検出力 | 各10,000試験 |
| RT・CRTの再生成 | 各試験4,999回 |
| 共分散推定 | 各割付設定100,000組の3系列。主要評価では2設定のみ |
| 優越性 | 両側5% |
| 非劣性 | 上側片側2.5% |
| スコア | 未調整・調整済みを同一試験上で評価 |
| 共分散構成 | 基本構成・再構成を同一試験上で評価 |
| 二値アウトカムの層別効果偏差 | 平均治療効果からの最大絶対偏差を0.12に固定 |

二値の生成モデルは p1_s=p0_s+Delta+d_s です。ここでプロファイル確率で重み付けした d_s の平均を0、最大絶対値を0.12とします。したがって全体の平均治療効果Deltaは維持されます。推論時の層別効果推定値を0.12に固定するのではありません。解析には従来どおり観測データから推定した層別効果を使用します。

全16個の主要二値シナリオで自動縮小なしに実現可能なことを確認しています。治療群の反応確率は全層・全主要シナリオで約0.2443～0.9760です。範囲(0.02,0.98)から外れた場合は、縮小・クリッピングせず停止します。連続アウトカムの設定と解析式は変更していません。

追加のsharp-null controlsを明示的に選択した場合のみ、偏差は0です。今回のM3用手順では主要32シナリオだけを本計算します。0.95、標本サイズ追加などは自動実行しません。

## 4. Python環境の準備

標準版CPython 3.13のネイティブarm64環境を使用します。実験的なfree-threaded版やRosetta経由のx86_64 Pythonは使用しません。

```bash
python3.13 --version
```

見つからない場合は、Python公式のmacOS用3.13 universal2インストーラーで標準版をインストールしてから進めてください。既に対応するPythonがある場合は再インストール不要です。

```bash
bash m3.sh setup
```

このコマンドは専用仮想環境を作成し、NumPy 2.3.5、SciPy 1.17.0、Numba 0.65.1、llvmlite 0.47.0をインストールします。既存のConda baseやシステムPythonにはインストールしません。`arm64`と各バージョンを確認し、14項目のテストを実行します。以後、手動で仮想環境をactivateする必要はありません。

Python実行ファイルを明示する場合は、例えば次のように指定できます。

```bash
SIGA_PYTHON=/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 bash m3.sh setup
```

実行開始後は、同じ仮想環境内のPython・数値ライブラリ・ソースコードを変更しないでください。変更が検出されると、古いチェックポイントとの混在を防ぐため停止します。

## 7. M3 Ultraで並列数を実測する

```bash
bash m3.sh benchmark
```

通常は8、12、16、20、24並列を試し、全32シナリオの短時間測定から、計算時間の推計が最も短い並列数を保存します。推計には本実行での保存・集計の全負荷や将来の他アプリの負荷は含まれないため、終了時間の保証ではありません。

推奨並列数はrecommended_workers.json、比較結果はbenchmarksフォルダに保存されます。計算開始後の判定や結果に応じてシナリオを選ぶものではなく、計算速度だけを比較します。

## 8. 本計算を実行する

```bash
bash m3.sh run
```

直前のベンチマークで選んだ並列数を自動使用します。主要32シナリオ、合計1,760,000試験を実行し、全件そろった後に自動集計します。ベンチマーク未実施の場合は最大12並列を使います。

並列数を明示する場合は次のようにします。

```bash
bash m3.sh run --workers 16
```

計算中はターミナルを閉じないでください。m3.shは長時間処理をcaffeinateとともに起動しますが、意図的なスリープ、再起動、シャットダウンは避けてください。別のM3ワークフローが同じ出力を変更しようとするとロックで停止します。

STATUS.jsonでcomplete=trueかつproduction_budget=trueを確認してください。不足シナリオがある状態で本計算の完成版として集計・保存することは拒否されます。
